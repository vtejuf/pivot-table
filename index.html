02 · pipeline

一条核心数据流，一组扩展挂载点

聚合、布局、几何、渲染各自独立；内置 feature 挂在阶段之间或渲染之后， 新增能力也复用同一组挂载点。

核心阶段 内置 feature 可挂载扩展点
  1. 01

    明细 rows

    输入

    业务明细，尚未聚合。每一行是一条原始记录。

    rows[]→rows[]
    挂载点 过滤 / 排序 / 折叠· 预处理（规划中）
  2. 02

    aggregate

    聚合

    按维度 key 分组，每个维度组合只保留一行，计算 count / sum / avg / min / max。

    rows[]→cube.rows[]
    挂载点 dual-measure· combineMeasures() 自定义度量 / 上卷· 派生 cube
  3. 03

    layoutPivot

    布局

    把成员取值编码成序号，通过仿射矩阵得到整数网格坐标，并生成可递归渲染的表头。

    cube.rows[]→layout
    挂载点 totals· rollupTotals(cube) + withTotals(layout) collapse· collapseCube() + 表头交互 展示布局派生· 排序 / 合并 / 自定义派生
  4. 04

    computePivotGeometry

    几何

    根据视口和滚动偏移计算屏幕矩形、可见范围与裁剪区；不接触 Canvas。

    layout→geometry
    挂载点 viewport / overscan· 表头尺寸
  5. 05

    renderPivot

    渲染

    绘制背景、网格线、文本和冻结表头；只遍历视口内的格子。

    layout + geometry→Canvas
    挂载点 heatmap· cellStyle overlay· renderWithOverlay() scrollbar· 渲染后叠加 + 自动隐藏 formatValue / theme· 渲染配置
交互回路 scrollX / scrollY 变化 → 重新计算几何 → 重绘 命中测试 / 下钻 → 重新进入 aggregate 或 layoutPivot
→
核心不依赖 feature。 依赖方向始终是 site / features → model / render；feature 只读取核心输出， 通过上面的挂载点扩展。架构守卫测试会阻止核心反向 import features。

03 · matrix transform

一次矩阵乘法，定位每个单元格

维度层级等价于混合进制数：父级粗定位，子级在父级划出的块内细定位。 整棵树最终折叠成一个固定矩阵。

一条记录被编码成增广向量，每个维度贡献一个成员序号 id，最后补一个常数项 1： 

v = [i₁, i₂, ..., i_D, 1]ᵀ

矩阵 M 的第 d 列是该维度所在轴的单位向量乘以 spand，最后一列是平移： 

[x, y]ᵀ = M · v

父子 span 满足乘积关系。父维度每变一级，跨过的行数正好是 子维度成员数乘以子维度 span： 

span_parent = n_child × span_child
span_d      = Π n_c（c 为 d 的后代）

cartesian 默认

每个父成员下补齐全局子成员，形成规则网格。span 与父成员无关， 整个布局是一个固定矩阵，代价是空单元格。

compact 紧凑

只排列数据中实际出现的组合，父成员块大小可变。没有全局固定矩阵， 但每条记录仍给出分段仿射变换。

  • 表头成员的 offset / size 直接对应 rowspan / colspan。
  • 重复维度组合默认报错，强制先聚合，不在布局层偷偷合并。
  • 每个轴支持一条层级链：单根、每个父维度最多一个子维度。

region > city > year

        [region] [city] [year] [1]
x  =  [   0       0      1     0 ] · v
y  =  [   3       1      0     0 ] · v
region span
3 = n_city × 1
city span
1
year span
1 · 列轴

city 有 3 个成员：region 每变一级跨 3 行，city 每变一级跨 1 行。

05 · performance

成本跟视口走，而不是跟整张表走

滚动时只遍历可见单元格；表头按 offset 二分剪枝；尺寸不变时复用 canvas 缓冲区；热力范围按 layout 缓存。

22,500 150×150 压测网格的总格数
50 480×280 数据视口实际绘制格数
1 次 每个 layout 只扫描一次热力范围

渲染层做了什么

  • 视口虚拟化：只遍历 visible 范围，总格数不参与每帧循环。
  • 单元格查找 O(1)：模型输出 cellMap。
  • 网格线合并为一次 beginPath() + stroke()。
  • 表头 offset 单调，二分跳过视口外成员及其子树。
  • 数据区与两块表头分别裁剪，冻结表头不触发整表重绘。
  • DPR 变换只设置一次；尺寸不变不重置 canvas 缓冲区。

方案取舍

  • Canvas 2D · 当前 约 1k–100k 格；零依赖，文本与矩形批量绘制快。
  • Canvas + 离屏缓存 连续滚动的大表；缓存表头、网格和斑马纹位图。
  • WebGL / WebGPU 十万到百万格、平滑缩放；文本排版和命中测试成本更高。
  • DOM / SVG 小表、文本选择、屏幕阅读器；节点多时性能下降明显。

自定义 feature

核心不依赖 feature；选一个挂载点，写只读核心输出的函数。

  1. 选挂载点 数据派生、布局派生、渲染配置或渲染后叠加。
  2. 写 createXxx() 返回 cellStyle、draw 或新的展示布局。
  3. 传给核心 renderPivot / renderWithOverlay，不修改核心。
